# Membuy — архитектура

Membuy — некастодиальный терминал для покупки и продажи мемкоинов Solana.
Приложение не хранит ни ключи, ни средства: сделки подписываются в кошельке пользователя.

## Слои

```

│ market.js  token.js  portfolio.js  components.js   │

                │ события (bus)     │ вызовы
```

## Интерфейс поставщика данных

Оба поставщика (`demo`, `live`) реализуют одно и то же:

```js
start()                 // запустить обновление
list(filter, query)     // → Promise<Token[]>   filter: trend | fresh | gain | vol
get(id)                 // → Promise<Token|null>
series(id, tf)          // → Promise<number[]>  tf: 1h | 1d | 1w
candles(id, tf)         // → Promise<{o,h,l,c}[]>  свечи для свечного графика
solUsd()                // → Promise<number>
```

`Token`: `{ id, sym, name, desc, mint, price, mc, vol24, chg24, ageDays, holders, liquidityUsd, hue, series, icon? }`.

## Путь сделки (live)

1. `swap.quote()` запрашивает котировку у Jupiter (`/quote`) с проскальзыванием и комиссией площадки.
2. Пользователь видит: сколько получит, минимум, влияние на цену, комиссию.
3. `swap.execute()` получает готовую транзакцию (`/swap`), кошелёк Phantom её подписывает и отправляет.
4. Сделка записывается в историю, баланс обновляется из сети.

## Заработок площадки

Jupiter удерживает `PLATFORM_FEE_BPS` с каждой сделки и переводит на `FEE_ACCOUNT`.
Пока `FEE_ACCOUNT` пуст, комиссия не берётся.

## Что работает только в демо и требует сервера

| Функция | Сейчас | Что нужно для настоящей работы |
|---|---|---|
| Лента, лайки, подписки | Хранятся в браузере пользователя | Сервер с базой данных и входом по подписи кошелька |
| Рейтинг трейдеров и отряды | Выдуманные участники + ваш демо-результат | Сервер, который считает результат по сделкам из сети |
| Рефералы | Код и ссылка-образец, начислений нет | Сервер, привязка приглашённых, выплаты доли комиссии |
| Реклама | Кампании видны только создателю, оплата не берётся | Приём оплаты, модерация, показ всем посетителям |
| Создание монеты | Монета только в браузере | Смарт-контракт в Solana и его аудит |
| Награды трейдерам | Описание идеи, фонд $0 | Доход от комиссий и правила выплат |

## Что не сделано

- Перпы (сделки с плечом) и акции: нужны лицензия и другая инфраструктура.

- Позиции в live-режиме ведутся локально по сделкам в приложении, а не читаются из сети.
- Нет своего сервера: лимиты публичных API и RPC общие для всех пользователей.
- Нет создания монет (площадки запуска) — для этого нужен смарт-контракт и аудит.
